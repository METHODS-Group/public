# METHODS Group public pages

GitHub Pages site for the METHODS Group, served from the root of `main` at https://methods-group.github.io/public/. The root page is the current sign-up sheet; past sheets are archived in their own folders. The group meetings page is at `/meetings/`.

## APMA 2570B project presentation sign-up (root page)

`index.html` (https://methods-group.github.io/public/) lets students in APMA 2570B, *Finite Element Methods for Nonlinear Problems* (Fall 2026), sign up for a course project presentation in class: one talk on Monday, Nov 23, and two each on Mondays, Nov 30 and Dec 7. It is rendered by `assets/presentations.js` (page styles in `assets/presentations.css`) from `data/schedule.json` and `data/signups.json`. Math in `$...$` in titles and descriptions is typeset with KaTeX from jsDelivr; if KaTeX fails to load, the raw text is shown.

How it works: pressing **Sign up** opens a pre-filled GitHub issue form (`.github/ISSUE_TEMPLATE/present.yml`) asking for the student's name, presentation title, and a brief description. When the issue is opened, the `Record sign-up` workflow runs `scripts/process.js`, which validates the request against `data/schedule.json` (slot exists, is open and before its `closes_at`, has room; the login holds no other slot, per `max_per_person`), appends the entry to `data/signups.json`, commits to `main`, then comments on the issue and closes it. Pages republishes on the push, so the entry appears within about a minute. Next to each entry, **Edit my sign-up** opens `update.yml` pre-filled with the current name, title, and description (what is submitted replaces them; only the student who signed up can edit), and **Cancel my sign-up** opens `cancel.yml`. Edits and cancellations still work after a slot's deadline. Each slot's `closes_at` is the start of that day's class (3:00 pm ET), with a `closed_message` for the issue comment. To fix a mistake, edit `data/signups.json` by hand (each sign-up is one object in `claims`) and push to `main`; to hold a slot, set its `open` to `false` and give it a reader-facing `note`. The issue forms match on labels `present`, `update`, and `cancel`, and fall back to the title prefixes `Present:`, `Update:`, and `Cancel:` if a label is missing. Run `node scripts/test.js` to check the processing logic.

## Archived sign-up sheets

`thomas-visit-2026/` (https://methods-group.github.io/public/thomas-visit-2026/) is the sheet for Thomas Surowiec's visit (October 13 to 15, 2026): one-on-ones, lunches, and the Tuesday evening outing. Its data lives in `thomas-visit-2026/data/` and it is drawn by `assets/app.js`. Its `schedule.json` sets `"archived": true`, so every slot shows as closed and no Claim, Join, or Cancel links are drawn; the workflow no longer reads its data. `scripts/test.js` still uses it as the fixture for the meeting and group logic in `scripts/process.js` (claims with a room choice, group joins, `reserved` and `blocked` slots, `closes_at` deadlines), which a future visitor sheet can reuse: put the new `schedule.json` and `signups.json` in `data/`, serve them with a copy of the visit page using `assets/app.js`, and restore the `claim.yml` and `join.yml` issue forms from this repository's history (they were removed in the commit that archived the visit).

To archive the current sheet before starting a new one, move `index.html` into a new folder with its `data/schedule.json` and `data/signups.json` (in a `data/` subfolder), point its asset links at `../assets/`, and make it read-only the way the visit sheet is (see `ARCHIVED` in `assets/app.js`).

## Group meetings page

`meetings/index.html` (https://methods-group.github.io/public/meetings/) lists the METHODS Group's weekly research meetings: the current semester's time, room, and Zoom link at the top, then an Upcoming/Past toggle over one card per talk (date, presenter, title, keywords, abstract, and links to slides, papers, and the Slack announcement). It is rendered by `assets/meetings.js` from `data/meetings.json`, with page-specific styles in `assets/meetings.css`.

To add or edit an entry, edit `data/meetings.json` on `main` and push; Pages republishes within about a minute. Each talk is one object in `talks` with `date` (`YYYY-MM-DD`), `presenter`, `title`, `abstract` (plain text; `<b>`, `<i>`, `<code>`, `<br>`, and `<a href="https://...">` are allowed, anything else is stripped), `keywords` (array), `links` (array of `{ "label", "url", "kind" }` with `kind` one of `slides`, `paper`, `code`, `video`, `announcement`), `status` (`upcoming` or `past`; the page groups by this field, not by today's date, so flip it after a talk happens), and an optional reader-facing `note`. Past talks are grouped by semester, derived from the date (Jan–May Spring, Jun–Aug Summer, Sep–Dec Fall) unless the entry sets `term`. The `semester` block at the top holds the current meeting time, location, Zoom link, and the sign-up sheet URL; bump `updated` when you change the file. Slides live in Slack, so slide links point at the Slack message that carries the file (login required); do not commit slide files to this repository.

A daily automated sync reads the announcements in #group-meetings (Slack channel `C083Q60ESNS`) and the sign-up sheet (Google Sheet `1jcNUKmm2uvCUYQMNY8rUwx8yA91LiCYYOIfEvkDuJIQ`, current-semester tab) and updates `data/meetings.json`. Channel announcements take precedence over the sheet when the two disagree about the same talk. The top-level `sync` object in the JSON records the channel id, the sheet id and tab, the precedence rule, the date of the last run, and `channel_last_ts`, the newest Slack message ts already reflected in the data (the next run only reads messages after it). Manual edits to the JSON are preserved: the sync overwrites a field only when the channel or the sheet later supplies a non-empty value for that same field.
